# 01 · 소리를 숫자로 읽기

1초짜리 소리를 16,000개의 숫자로 적으면 그 안에서 440Hz를 어떻게 찾아낼까? 먼저 파형을 만들고, 짧게 잘라 각 구간에서 가장 강한 주파수를 찾는다. 필요한 소리는 코드가 만들며 모든 결과를 숫자와 그래프로 확인할 수 있다. [실습 노트북 열기](./01_waveform.ipynb)

## 셀 1–6 · 샘플 개수와 소리 높이

```python
num_samples = sample_rate * duration
waveform = torch.zeros(1, num_samples)
```

`sample_rate = 16_000`은 1초를 숫자 16,000개로 기록한다는 뜻이다. `duration`이 1이면 `torch.zeros`가 0으로 채운 한 줄에 숫자 16,000개를 만든다. 출력 `[1, 16000]`에서 앞의 1은 채널 하나, 뒤의 16,000은 샘플 개수다. 길이를 2초로 바꾸면 `[1, 32000]`이 된다.

```python
time = torch.arange(num_samples) / sample_rate
wave = 0.2 * torch.sin(2 * math.pi * frequency * time)
waveform = wave.unsqueeze(0)
```

- `time`은 각 샘플의 시각이다. 첫 세 값은 0초, 1/16000초, 2/16000초다.
- `sin(...)`은 위아래로 반복되는 파형을 만든다. `frequency`는 초당 진동 횟수이고 앞의 `0.2`는 진폭을 정한다.
- `unsqueeze(0)`은 맨 앞에 채널 축 하나를 붙인다. 2초짜리 440Hz와 880Hz 파형은 모두 `[1, 32000]`이다.

셀 6은 두 소리에서 같은 0.01초, 즉 160개 샘플을 그린다. 440Hz는 이 구간에서 4.4번, 880Hz는 8.8번 진동해서 880Hz 곡선이 두 배 촘촘하다.

## 셀 7–10 · 동시에 울린 두 음과 차례로 울린 두 음

| 코드 | 만든 소리 | 그림에서 읽을 것 |
|---|---|---|
| `mixed_wave = wave_440 + wave_880` | 440Hz와 880Hz를 동시에 낸다. | `rfft` 결과에서 두 주파수에 봉우리가 생긴다. 440Hz의 진폭은 0.2, 880Hz는 0.1로 만들었으므로 440Hz 봉우리가 더 높다. |
| `waveform = torch.cat([wave_440, wave_880])` | 앞 0.5초에는 440Hz, 뒤 0.5초에는 880Hz를 낸다. | 스펙트로그램의 밝은 선이 0.5초 근처에서 440Hz에서 880Hz로 올라간다. |

`torch.fft.rfft`는 파형을 주파수별 성분으로 나누고, `.abs()`는 각 성분의 크기를 구한다. `rfftfreq`는 그래프의 각 칸이 몇 Hz인지 알려준다.

`torch.stft`는 이 계산을 **짧은 구간마다** 반복한다. `n_fft=400`은 25ms를 한 번에 보고, `hop_length=160`은 다음 창을 10ms 뒤에서 시작한다는 뜻이다. `hann_window`는 창의 양 끝을 부드럽게 줄인다. 그래프의 가로축은 시간, 세로축은 주파수, 밝기는 상대적인 세기다. 가장 강한 칸을 0dB로 맞췄다.

## 셀 11–15 · 특징 숫자에서 글자 후보까지

| 노트북에서 읽을 코드 | 배열 모양 | 무엇이 달라졌나? |
|---|---|---|
| `magnitude` | `[201, 101]` | 실수 샘플 400개의 스펙트럼에서 0Hz부터 절반 지점까지 400 ÷ 2 + 1 = 201칸을 읽었다. 시간축에는 101개 시점이 있다. |
| `magnitude.transpose(0, 1)` | `[101, 201]` | 한 줄을 읽으면 한 시점의 주파수 201개가 보인다. |
| `features.unsqueeze(0)` | `[1, 101, 201]` | 음성 한 건을 나타내는 배치 축이 생겼다. |
| `projection = nn.Linear(201, 64)` | 출력 `[1, 101, 64]` | 시간 순서를 유지하면서 매 프레임의 특징을 64개로 바꾼다. |
| `classifier = nn.Linear(64, 3)` | 출력 `[1, 101, 3]` | 각 프레임에 세 가지 토큰 후보의 점수가 생긴다. |

마지막 두 층은 특징과 점수의 **모양을 연습**하는 예제다. 가중치는 처음에 무작위로 정해지므로 점수는 실행마다 달라질 수 있다. 셀 15에서는 CTC 규칙만 눈으로 확인하려고 토큰 번호를 직접 넣는다.

```python
frame_ids = [1, 1, 2, 2, 0]   # 가, 가, 나, 나, 빈 토큰
```

`previous_id`는 직전 번호를 기억한다. 연속해서 나온 같은 번호는 한 번만 쓰고, 빈 토큰 0은 쓰지 않으면 결과는 **가나**다. 반대로 `[1, 0, 1]`에서는 빈 토큰이 두 ‘가’를 떼어 놓으므로 **가가**가 된다.

## 셀 16–21 · 0.2초 조각에서 25ms 프레임 꺼내기

셀 16에서 입력을 **1초 내내 440Hz인 파형**으로 새로 만든다. 실제 설정 `chunk_duration = 0.2`를 따라 3,200개 샘플씩 다섯 조각이 나온다. 조각은 한 번에 받는 양이고, 프레임은 분석하려고 들여다보는 창이다.

```python
while len(buffer) >= window_size:
    all_frames.append(buffer[:window_size])
    buffer = buffer[hop_size:]
```

1. 샘플이 400개 이상 모이면 맨 앞 400개를 프레임 하나로 꺼낸다.
2. 다음 창은 160개 뒤에서 시작한다. 그래서 사용한 400개 중 뒤쪽 240개는 다음 창에서도 본다.
3. 첫 조각에서는 0ms, 10ms, …, 170ms에 시작하는 창 **18개**가 완성된다. 다음 창은 180–205ms인데 소리는 200ms까지만 들어와 있다.
4. 180–200ms의 320개를 보관하고 두 번째 조각의 첫 80개를 붙인다. `torch.equal(next_frame, waveform[2880:3280])`의 출력 `True`는 이어 붙인 값이 원래 파형의 같은 구간과 일치한다는 뜻이다.

이후 네 조각에서는 20개씩 완성돼서 결과는 **18 + 20 × 4 = 98개**, 모양은 `[98, 400]`이다. 마지막 `len(buffer)`는 320이다. 400개가 모일 때만 창을 꺼내도록 했으므로 여기서 멈춘다. 앞의 STFT는 기본 설정으로 양 끝을 패딩해 101개 시점을 계산했고, 이 반복문은 실제 샘플로 완성한 98개 창을 센다.

## 셀 22–23 · 98개 창에서도 440Hz를 찾을 수 있을까?

```python
strengths = torch.fft.rfft(all_frames * window, dim=1).abs()
peak_bins = strengths.argmax(dim=1)
peak_hz = frequencies[peak_bins]
```

`dim=1`은 각 행 안의 400개 샘플을 따라 주파수를 계산하라는 뜻이다. `strengths`의 모양은 `[98, 201]`이다. `argmax`는 각 행에서 가장 강한 **칸 번호**를 고르고, `frequencies[peak_bins]`는 그 칸을 Hz로 읽는다. 한 칸 간격은 16,000 ÷ 400 = 40Hz이므로 **11번 칸은 440Hz**다. 처음 다섯 값은 모두 440.0이었고, 전체 출력은 **98개 중 98개**였다.
